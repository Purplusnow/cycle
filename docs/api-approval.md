# 경륜 오픈API — 신청 목록과 실측 결과

> **2026-08-14: 12개 전부 자동승인.** 아래 신청 목록은 그대로 두고, 승인 뒤
> 프로브로 확인한 사실을 맨 아래 「프로브 실측」에 적었다. **신청 전에 세운
> 추측 중 틀린 것이 셋 있고, 그 셋이 설계를 바꾼다** — 거기부터 읽어도 된다.


공공데이터포털에서 **서울올림픽기념국민체육진흥공단 경주사업총괄본부**가 내는
API는 34개이고 그중 **경륜이 12개**(경정 19개, 스피드온 3개)다. 12개 전부의
Swagger 명세를 `config/openapi/<데이터셋번호>.json` 에 원본 그대로 받아 뒀다 —
경로·파라미터에 추측한 값이 하나도 없다.

신청은 `https://www.data.go.kr/data/<데이터셋번호>/openapi.do` 에서 한다.

**호스트 접두어가 경정과 같은 `B551014`** 라, 발급받은 인증키 하나로 경정·경륜이
모두 열린다. `boatai` 의 클라이언트 코드(`resultType=json` 필수, `pageNo`·
`numOfRows` 필수, 미승인은 HTTP 403)가 그대로 통한다.

### 15107830 · 출주표 — `SRVC_OD_API_CRA_RACE_ORGAN/TODZ_API_CRA_RACE_ORGAN_I`

필수 `serviceKey`, `resultType` / 옵션 `pageNo`, `numOfRows`, `meet_nm`,
`stnd_yr`, `week_tcnt`

47개 필드. 경주 전에 확정되는 정보를 거의 다 담는다.

* **전법 입상 횟수** — `pre_win_cnt`(선행) `pas_win_cnt`(젖히기)
  `brk_win_cnt`(추입) `mrk_win_cnt`(마크). 경륜에서 승부를 가르는 축이 이것이다.
  경정의 '코스'에 해당하는 자리를 여기가 차지한다.
* **기량** — `win_rate` `high_rate`(연대율) `high_3_rate`(삼연대율)
  `racer_grd_cd`(등급) `racer_grd_bef_cd`/`racer_grd_cur_cd`(등급 조정 전후)
  `tot_tms_avg_scr`(종합 평균득점) `area_tms3_avg_scr`(광명 평균득점)
* **장비·신체** — `gear_rate`(기어배수) `rec_200m_scr`(200m 기록) `racer_age`
  `trng_plc_nm`(훈련지) `period_no`(기수)
* **최근 3회전 성적** — `bf1~bf3_meet_nm`(장소) `bf1~bf3_day1_ymd`(경주일자)
  `bfN_day1~3_rank`(일차별 순위). 회차가 3일 편성이라 회전당 3개 착순이 온다.
* **경주 조건** — `race_len`(경주길이) `round_cnt`(주회수) `dptre_tm`(출발시각)
  `back_no`(등번호) `color_nm` `meet_nm`(경륜장)
* **`race_ymd` 가 출주표 안에 있다.** 경정에서는 회차↔날짜를 잇느라 '홈페이지
  출주표' API 를 따로 붙여야 했는데, 경륜은 그 다리가 필요 없다.

### 15143989 · 경주결과순위 — `SRVC_CRA_RACE_RANK/TODZ_CRA_RACE_RANK`

필수 `serviceKey`, `pageNo`, `numOfRows`, `resultType` /
옵션 `stnd_year`, `tms`, `day_ord`, `race_no`, `race_day`, `racer_no`, `racer_nm`

**파라미터 이름이 다른 API 와 어긋난다** — `stnd_year`·`tms`·`day_ord`·`race_day`
(다른 곳은 `stnd_yr`·`week_tcnt`·`day_tcnt`·`race_ymd`). 경정에서 똑같은 함정을
겪었고, `boatai` 의 `ALT_PARAM_NAMES` 변환을 그대로 옮기면 된다. 낙차사고
(15119695) 도 같은 계열이다.

필수 파라미터가 인증·페이징뿐이라 **연 단위 일괄 수집이 된다.** 선수 단위 착순이
여기 있으므로 학습 레이블의 근간이다. 다만 포털 명세에 응답 필드 정의가 비어
있어(`definitions` 가 없다) **실제 필드는 승인 후 프로브로 확인해야 한다.**

### 15107845 · 배당률 — `SRVC_OD_API_CRA_PAYOFF/TODZ_API_CRA_PAYOFF_I`

필수 `serviceKey`, `resultType` / 옵션 `pageNo`, `numOfRows`, `stnd_yr`,
`week_tcnt`, `day_tcnt`

`pool1_val`(단승) `pool2_1_val`·`pool2_2_val`(연승1·2) `pool4_val`(쌍승)
`pool5_val`(복승) `pool6_val`(삼복승), `race_ymd` 포함.

**경정보다 훨씬 싸다.** 경정 배당률은 4개 파라미터가 전부 필수라 경주 하나씩만
뽑혔는데, 경륜은 일차 단위로 한 번에 온다 — 호출 수가 10분의 1 아래로 떨어진다.

### 15107816 · 경주결과 — `SRVC_TODZ_CRA_RACE_RESULT/TODZ_API_CRA_RACE_RESULT`

필수 `serviceKey`, `resultType`, **`stnd_yr`, `meet_nm`, `week_tcnt`,
`day_tcnt`, `race_no`** / 옵션 `pageNo`, `numOfRows`

`rank1~3`(1~3순위) + 승식 배당 6종 + `race_ymd`.

**여기가 가장 비싸다.** 경주 하나를 뽑는 데 파라미터 5개가 전부 필수라, 24년치를
채우려면 경주 수만큼 호출해야 한다(경륜장 3곳 × 회차 × 3일차 × 경주). 일일 한도
안에 넣으려면 백필을 여러 날에 나눠야 한다.

→ **착순 레이블은 15143989(일괄 수집 가능)로 만들고, 15107816 은 배당 결손을
메우는 용도로만 쓰는 편이 낫다.** 신청은 해 두되 수집 전략은 이렇게 간다.

## 신청할 때 알아둘 것

* **한 번에 12개 다 신청해도 된다.** 실제로 12개 전부 **자동승인**됐다
  (`boatai` 는 19개 중 6개만 자동승인되고 13개가 심의로 넘어갔던 것과 다르다).
  미승인 API 는 오류 코드가 아니라 **HTTP 403** 으로 돌아오므로, 승인 목록을
  코드에 적어 두지 않으면 매 실행마다 403 을 맞으면서 파이프라인은 성공으로
  끝나 '자료가 원래 없는 것'처럼 보인다.
* 1순위 4개 중 **15107830·15143989·15107845** 이 셋만 승인돼도 예측·검증
  파이프라인은 닫힌다. 15107816 은 없어도 된다(배당은 15107845 에 있다).

## 프로브 실측 (2026-08-14)

```bash
PYTHONPATH=src python -m cycleai.kcycle.probe --zero-pad
```

오퍼레이션 18개 중 **17개 정상**, 1개(연간경주일정)는 자료 자체가 없다.
결과는 `config/api_fields.json`(응답 필드·표본)과
`config/endpoints.resolved.json`(확정 경로)에 남는다.

### 신청 전 추측 중 틀린 것 셋

**1. 연간경주일정은 빈 API 다.** 「'자료실'이라는 이름에 속으면 안 되는 API」라고
적었는데, 반대였다. 연도·월을 어떻게 주든 2024·2025·2026 전부 `totalCount=0`
이다. 코드 00 정상 응답에 자료만 없으므로 권한 문제가 아니다.
**개최일은 출주표의 `race_ymd` 로 잡는다.**

**2. 오퍼레이션 세그먼트는 대소문자를 가린다 — 그리고 명세가 틀렸다.**
자료실 서비스의 명세는 오퍼레이션 8개를 전부 대문자로 적어 놨는데, 실제
게이트웨이는 5개를 **소문자로만** 받는다. 같은 서비스 안에서 스타트사진·
경주동영상은 대문자라야 한다. 규칙이 없다 — 실측한 값만 믿을 수 있다.

| 오퍼레이션 | 대문자 | 소문자 |
|---|---|---|
| `..._WEB_SCHEDULE` / `_CYCLE_NEWS` / `_PDS_MASTER` / `_PLAN_PGM` / `_GRND_PGM` | 코드 12 | **정상** |
| `..._WEB_STRT_PHOTO` / `_CYCLE_RACE_VIDEO` | **정상** | 코드 12 |

**3. 선수정보(15107844)는 '마스터'가 아니라 연도별 성적 집계다.** 명세에 응답
정의가 없어 '선수 페이지 표시용'으로 낮춰 잡았는데, 실제로는 22필드다 —
`rank1_tcnt`~`rank9_tcnt`(착순별 횟수), `win_rate`·`high_rate`·`high_3_rate`,
`down_po_cnt`(낙차), `elim_tcnt`(실격), `run_cnt`·`run_day_tcnt`.
**연도 단위 사전(prior) 값으로 쓸 수 있다** — 2순위가 아니라 1.5순위다.

### 조용히 0건으로 실패하는 것 넷

오류가 아니라 **빈 결과**로 돌아오기 때문에, 파라미터를 만드는 한 곳
(`endpoints.to_api_params`)에서 강제한다. 호출부마다 손으로 맞추면 언젠가 한
곳을 빠뜨리고 그 API 만 조용히 비게 된다.

* **`race_no`·`week_tcnt`·`tms` 는 2자리 0채움.**

  | 파라미터 | `"09"` | `"9"` |
  |---|---|---|
  | 출주표 `week_tcnt` | 448건 | **0건** |
  | 경주결과순위 `tms` | 182건 | **0건** |
  | 경주결과 `race_no` | 1건(`"01"`) | **0건**(`"1"`) |

  **한 자리 회차(=연초 두 달)에서만 터진다.** 회차별로 훑는 수집기를 여름에
  만들면 통과하고 이듬해 1월에 조용히 빈다. 이름을 바꾼 **뒤에** 0채움을 걸어야
  한다 — 순서를 뒤집으면 `tms` 로 이름이 바뀐 쪽이 그냥 지나간다.
* **날짜 파라미터는 8자리.** 출주표가 주는 `"2026.01.02"` 를 조조연습현황에
  그대로 넘기면 0건이다. `norm_ymd` 가 막는다.
* **경륜장명에 꼬리 공백이 붙는다.** 출주표·상대전적은 `"광명  "`, 경주결과·
  경주결과순위는 `"광명"`. 조인 키로 그대로 쓰면 한 건도 붙지 않는다.
  `norm_meet` 을 통과시킨다.
* **페이지 상한에 딱 걸린 숫자를 의심하라.** 상대전적은 연 62,874행이라
  페이지가 63장인데 `max_pages=60` 으로 두었더니 정확히 **60,000행**에서
  잘렸다. 오류도 경고도 없었고, 딱 떨어지는 숫자가 유일한 단서였다.

### 경주결과순위는 연 단위로 훑으면 안 된다

정렬이 고정돼 있지 않아 페이지를 넘기면 같은 행이 두 번 오고 어떤 행은 한
번도 오지 않는다. 2026년을 페이지 크기만 바꿔 훑은 실측:

| numOfRows | 받은 행 | 유니크 |
|---|---|---|
| 1000 | 14,455 | 11,349 |
| 500 | 14,455 | 10,957 |
| 300 | 14,455 | 10,630 |

**페이지 크기가 결과를 바꾼다는 것은 페이지 사이에 순서가 없다는 뜻이다.**
회차 하나는 한 페이지(1000행)에 다 들어가므로 페이지를 넘길 일이 없다 —
회차별로 훑으면 39회 호출로 14,455건 전부가 중복 없이 들어오고 `totalCount`
와 정확히 일치한다.

출주표(11,200행 / 12페이지)와 배당률(1,568행)은 같은 문제가 없었다. 연 단위로
훑어도 받은 행과 유니크가 `totalCount` 와 모두 일치한다.

### 날짜 표기가 API 마다 다르다

정규화 계층이 반드시 필요한 이유다. 같은 기관, 같은 게이트웨이인데도:

| API | 필드 | 실제 값 |
|---|---|---|
| 출주표 | `race_ymd` | `2026.01.02` (점 구분) |
| 배당률 | `race_ymd` | `20260102` |
| 경주결과 | `race_ymd` | `0102` (**월일만** — 연도는 `stnd_yr`) |
| 경주결과순위 | `race_day` | `20260613` |
| 출주표 최근성적 | `bf1_day1_ymd` | `1205` (월일만) |

### 응답에서 드러난 것

* **출주표에 선수번호가 없다.** `racer_nm` 만 있고 `racer_no` 가 없다. 반면
  경주결과순위에는 `racer_no`(`20100013`)가 있다. **피처와 레이블을 이름으로
  이어야 한다는 뜻이라 동명이인이 곧바로 위험**이다. 선수정보·회차별 득점·
  상대전적·배번집계도 전부 이름만 준다. 이름+등급+기수로 키를 만들지, 경주결과
  순위의 번호를 이름에 역매핑할지 정해야 한다.
* **경주결과의 배당 필드가 명세보다 많다.** 명세는 6종인데 실물은 `pool1`,
  `pool2`, `pool4`~`pool8` 로 8칸이고, **값에 조합이 같이 들어 있다** —
  `pool6_val = "(2-7-5)3.4"`, `pool2_val = "(2)1.2 (7)2.1"`. 배당률 API 는
  숫자만 주므로, **적중 조합까지 확인하려면 경주결과 쪽을 봐야 한다.**
* **착순은 원문자에 배번이 박혀 온다.** `rank1 = "②이길섭"`. 파싱해야 한다.
* **낙차사고의 필드명이 거짓말한다.** `racer_no1`~`racer_no7` 의 값이 번호가
  아니라 **선수명**이고, `down_indu1_yn`·`down_indu7_yn` 은 Y/N 이 아니라
  `"공정위반"` 같은 사유 문자열이다.
* **제재선수의 `p_johang` 은 `<BR>` 이 섞인 HTML 덩어리**이고, 해당 경주가
  `"26년광명제25회2일차15경주"` 처럼 문장 안에 박혀 있다. 구조화하려면
  파싱해야 한다. `racer_id` 는 `"23-018"` 형식이라 다른 API 의 선수번호와
  형태가 다르다.
* **등급 표기가 API 마다 다르다.** 출주표 `racer_grd_cd = "선발"`, 선수정보
  `racer_grd_cd = "B3"`. 같은 필드명인데 값 체계가 갈린다.
* **선수정보에 8·9착이 있다**(`rank8_tcnt`·`rank9_tcnt`). 7명 경주이므로
  실격·기권 자리로 보인다. 레이블을 만들 때 확인이 필요하다.
* 2026년 자료 규모: 출주표 11,200행 · 경주결과순위 14,455행 · 상대전적
  44,520행 · 경주동영상 16,292행(2019~).

## 설계에 영향을 주는 경정과의 차이

| | 경정 | 경륜 |
|---|---|---|
| 출전 수 | 6정 | **7명** |
| 시행처 | 미사리 한 곳 | **광명·창원·부산** — `meet_nm` 축이 생긴다 |
| 편성 | 회차 2일(수·목) | **회차 3일** (`bfN_day1~3_rank`) |
| 자리의 의미 | 정번 = 코스, 1코스 우위 압도적 | 배번은 출발 위치일 뿐, **전법·라인이 결정** |
| 장비 | 모터·보트 추첨 배정이 큰 변수 | 자전거는 선수 소유 — `gear_rate`·200m 기록 |
| 회차↔날짜 | 별도 API 로 이어야 함 | **출주표에 `race_ymd` 가 있다** |
| 사전 작전 정보 | 틸트각(미승인) | **없음** |
| 배당 수집 | 경주 단위(비쌈) | 일차 단위(쌈) |
| 결과 수집 | 연 단위 일괄 | 순위는 일괄, 경주결과는 경주 단위(비쌈) |
