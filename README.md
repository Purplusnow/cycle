# cycleai — 경륜 예측 (개인 참고용)

광명 경륜 경주를 공공데이터포털 오픈API 로 모아 승률을 예측하고, **예측을
발주 전에 확정 저장한 뒤** 실제 결과·배당과 대조해 적중률과 회수율을 낸다.
경정 버전(`~/dev/boatai`)의 구조를 따르되, 경륜의 성질에 맞춰 바꿨다.

## 먼저 — 이 프로젝트에서 가장 중요한 한 줄

**경륜은 득점 하나로 대부분 설명되는 종목이다.** 출주표의 종합 평균득점이 가장
높은 선수를 그냥 찍기만 해도 단승이 **59.7%** 맞는다. 이 모델은 **60.9%** 다.
모델이 보탠 몫은 **1.2%p** 이고, 그 사실을 첫 화면 맨 위에 적어 두었다.

경정에서는 '1코스 고정' 이라는 베이스라인이 36% 였고 모델이 47.8% 였다 —
차이가 12%p 였다. 경륜은 그렇지 않다. **적중률 60% 라는 숫자만 크게 적으면
그 자체로 거짓말이 된다.**

| | 경정(boatai) | 경륜(cycleai) |
|---|---|---|
| 모델 단승 적중률 | 47.8% | **60.9%** |
| 베이스라인 | 1코스 고정 36.1% | **득점 최고 59.7%** |
| 모델이 보탠 몫 | +11.7%p | **+1.2%p** |
| 자리(정번/배번) 고정 | 1코스 36.1% (압도적) | 배번1 **16.2%** (무작위 14.3%) |

마지막 줄이 두 종목의 차이를 요약한다. **경정에서 자리는 유리함이고, 경륜에서
자리는 그냥 출발 위치다.** 경륜에서 그 자리를 차지하는 것은 전법과 라인이다.

## 그다음 — 회수율 146% 를 그대로 믿으면 안 되는 이유

검증에서 **삼복승 누적 회수율이 146%** 로 나왔다. 공제율을 생각하면 있을 수
없는 값이라 파고들었더니, 회수액 **상위 1% 를 눌러 다시 계산하면 87.3%** 였다.
연도별로도 90%대에서 170%대까지 널뛴다.

즉 그 146% 는 **수백 배짜리를 몇 번 맞힌 기록**이지 반복 가능한 우위가 아니다.
그래서 이 저장소는 어디서든 회수율을 낼 때 **절단 회수율을 나란히 낸다.**

* `verify` 의 승식별 표에 `절단` 열이 붙는다.
* `strategy` 의 선택 규칙 표는 **절단 회수율로 정렬**한다. 누적 회수율로 줄을
  세우면 꼬리가 가장 두꺼운 승식이 언제나 1위로 올라오고, 그 위에서 자금
  시뮬레이션을 돌리면 시드 100만원이 8,060% 로 불어난 그래프가 화면에 나간다.
* 화면에도 두 값을 나란히 싣고, 차이가 큰 규칙에는 경고 상자를 띄운다.

절단 기준으로 가장 좋은 규칙은 `연승-고신뢰-특선`(97.6% / 절단 96.3%)이고,
**여전히 100% 아래다.**

## 자료 — 무엇을 쓸 수 있나

경주사업총괄본부가 내는 API 34개 중 **경륜이 12개**다. 12개 전부 자동승인이고,
기관코드가 경정과 같은 `B551014` 라 **인증키 하나로 경정·경륜이 모두 열린다.**

신청 목록과 실측 결과는 [`docs/api-approval.md`](docs/api-approval.md) 에 있다.

| API | 쓰임 |
|---|---|
| 출주표 | **피처 전부** (전법·득점·최근 3회전, 47필드) |
| 경주결과순위 | **착순 레이블** (2003~, 34만 행, 창원·부산 포함) |
| 배당률 | 승식 배당 (연 단위 일괄) |
| 경주결과 | 조합이 붙은 배당 + 1~3착 (경주 단위, 비쌈) |
| 선수정보 | 연도별 착순 분포 — 사전값 |
| 낙차사고 | 낙차·사고 이력 |
| 상대전적 | **동반입상 횟수** — 라인 대리 지표 |
| 제재선수·회차별 득점·배번집계·운영정보·자료실 | 보조·콘텐츠 |

### 광명만 예측한다

**출주표는 광명 것만 나온다.** 2005~2026 전 연도를 확인했고 `meet_nm` 이 전부
`광명` 이다. 창원·부산은 `meet_nm` 을 지정해도 0건이다. 피처가 없으니 예측할
수 없다.

다만 **착순은 세 경륜장 것을 모두 받는다.** 광명 선수가 원정에서 뛴 결과가
그 선수의 폼이기 때문이다(2026년 기준 광명 11,088 · 창원 1,904 · 부산 1,463).

## 조용히 실패하는 것들 — 이 저장소가 실제로 겪은 사고

전부 **오류가 아니라 빈 결과**로 돌아온다. 그래서 파라미터를 만드는 한 곳
(`kcycle/endpoints.py:to_api_params`)에서 강제하고, 테스트로 지킨다.

### 1. 회차가 한 자리일 때만 조용히 빈다

`week_tcnt`·`tms`·`race_no` 는 **2자리 0채움 문자열**이어야 한다.

| 파라미터 | `"09"` | `"9"` |
|---|---|---|
| 출주표 `week_tcnt` | 448건 | **0건** |
| 경주결과순위 `tms` | 182건 | **0건** |
| 경주결과 `race_no` | 1건 (`"01"`) | **0건** (`"1"`) |

**1~9회차는 연초 두 달이다.** 회차별로 훑는 수집기를 여름에 만들면 통과하고
이듬해 1월에 조용히 빈다. 두 자리 회차만 보고 '되는구나' 하고 넘어가기 딱 좋다.

이름을 바꾼 **뒤에** 0채움을 건다. 순서를 뒤집으면 `week_tcnt` 만 채워지고
`tms` 로 이름이 바뀐 쪽은 그냥 지나간다.

### 2. 경주결과순위는 연 단위로 훑으면 안 된다

정렬이 고정돼 있지 않아 페이지를 넘기면 같은 행이 두 번 오고 어떤 행은 한
번도 오지 않는다. 실측 — 2026년을 페이지 크기만 바꿔 훑었을 때:

| numOfRows | 받은 행 | 유니크 |
|---|---|---|
| 1000 | 14,455 | 11,349 |
| 500 | 14,455 | 10,957 |
| 300 | 14,455 | 10,630 |

**페이지 크기가 결과를 바꾼다는 것은 페이지 사이에 순서가 없다는 뜻이다.**
회차 하나는 한 페이지에 다 들어가므로 페이지를 넘길 일이 없다 — 회차별로
훑으면 39회 호출로 14,455건 전부가 중복 없이 들어오고 `totalCount` 와 정확히
일치한다.

### 3. 날짜 표기가 API 마다 다르다

| API | 필드 | 실제 값 |
|---|---|---|
| 출주표 | `race_ymd` | `2026.01.02` (점 구분) |
| 배당률 | `race_ymd` | `20260102` |
| 경주결과 | `race_ymd` | `0102` (**월일만** — 연도는 `stnd_yr`) |
| 경주결과순위 | `race_day` | `20260613` |
| 출주표 최근성적 | `bf1_day1_ymd` | `1205` (월일만) |

출주표가 주는 `"2026.01.02"` 를 조조연습현황에 그대로 넘기면 0건이다.

### 4. 경륜장명에 꼬리 공백이 붙는다

출주표·상대전적은 `"광명  "`, 경주결과·경주결과순위는 `"광명"`. 조인 키로
그대로 쓰면 오류 없이 한 건도 붙지 않는다.

### 5. 명세가 틀린 곳 — 오퍼레이션은 대소문자를 가린다

자료실 서비스(`SRVC_WEB_CRA_MBR_INFO`)의 명세는 오퍼레이션 8개를 전부 대문자로
적어 놨는데, 실제 게이트웨이는 5개를 **소문자로만** 받는다(코드 12). 같은
서비스 안에서 스타트사진·경주동영상은 대문자라야 한다. 규칙이 없다.

### 6. 페이지 상한에 딱 걸린 숫자를 의심하라

상대전적은 연 62,874행이라 페이지가 63장인데 `max_pages=60` 으로 두었더니
정확히 **60,000행**에서 잘렸다. 오류도 경고도 없었다 — **딱 떨어지는 숫자가
유일한 단서였다.**

## 쓰는 법

```bash
python -m cycleai.kcycle.probe --zero-pad   # 승인·경로·응답필드·0채움 확인
python -m cycleai.kcycle.collect backfill   # 2003~올해 (약 1,500회 호출)
python -m cycleai.kcycle.collect daily      # 매일: 올해분 갱신
python -m cycleai.model train               # 학습 + 워크포워드 검증
python -m cycleai.predict upcoming          # 발주 전 경주의 예상 확정 저장
python -m cycleai.predict backfill          # 과거 경주 표본외 예측 (검증용)
python -m cycleai.calibrate                 # ★ 기호 기준 보정
python -m cycleai.verify --version v1-oos   # 적중률·회수율 검증
python -m cycleai.strategy                  # 베팅 전략 검토
python -m cycleai.audit --days 30 --strict  # 자료 결손 점검
python -m cycleai.site                      # dist/ 로 정적 사이트 빌드
```

경주일(금·토·일) 흐름은 `daily` → `predict upcoming` → `site` →
(경주 후) `daily` → `verify` → `audit` → `site` 순이다.

### 사이트

```bash
python -m cycleai.site --db data/cycleai.sqlite --out dist
python -m http.server 8000 -d dist    # http://localhost:8000
```

| 페이지 | 내용 |
|---|---|
| `/` | 다가올 경주(1순위·기호·승률), 고배당 적중, 최근 결과, 검증 요약 |
| `/race/<경주키>/` | **상세예상지** — 예상판, 라인 후보, 전개 시뮬레이션, 체크포인트, 전법 성향, 출주표, 최근 3회전, 확정배당 |
| `/day/<YYYYMMDD>/` | 그날 전 경주 |
| `/results/` | 결과 아카이브 (빗나간 예상 포함) |
| `/accuracy/` | 승식별 적중률·회수율(절단 포함), 배번별·급별·월별 |
| `/strategy/` | 베팅금 규칙(마틴게일 등)과 선택 규칙 시뮬레이션 |

화면이 지키는 것:

* **베이스라인을 적중률 옆에 둔다** — 경륜에서 '적중률 60%' 는 그 자체로
  아무 말도 하지 않는다. 득점 최고(59.7%)와 나란히 놓아야 뜻이 생긴다.
* **회수율은 절단값과 함께** — 100% 를 넘는 승식이 있어도, 그 값이 무엇에
  매달려 있는지를 같은 표에서 보게 한다.
* **공개 / 검증 배지** — 발주 전에 확정 저장한 `v1` 과 시간순 교차검증
  `v1-oos` 를 배지로 구분한다. 표에서 섞이면 며칠 뒤의 나는 둘을 같은 것으로
  읽는다.
* **배번은 색 배경 + 큰 숫자** — 실제 배번 색(1 백 · 2 흑 · 3 적 · 4 청 ·
  5 황 · 6 녹 · 7 분홍)을 배경으로 쓰고 숫자를 그대로 크게 적는다. 색만으로
  구분하면 색각 이상에서 3(적)과 6(녹)이 섞인다.
* **경주는 항상 1R 부터** — 하루 안의 순서는 시행 순서이고, 그것이 사람이
  경주를 찾는 순서다. 날짜만 최신이 위로 온다.
* **표본 수를 함께 적는다** — 연대율 옆의 '25회' 는 그 백분율을 얼마나 믿을지
  알려 준다.
* **조사를 붙인다** — `korean.josa`. '김용진 가 7착' 이 나가면 문장 하나가
  어색한 데서 끝나지 않는다. 자동으로 만든 티가 나는 순간, 옆에 있는 숫자도
  대충 만든 것처럼 읽힌다.

## 경륜이라서 다른 점

### 자리가 아니라 전법이다

출주표는 전법별 입상 횟수를 준다 — `pre_win_cnt`(선행) `pas_win_cnt`(젖히기)
`brk_win_cnt`(추입) `mrk_win_cnt`(마크). 경정에서 '코스별 6개월 연대율'이
차지하던 자리를 이것이 대신한다.

피처로는 **횟수보다 비율**을 쓴다. 횟수는 경력 길이에 끌려간다 — 마크 20회는
베테랑이면 흔하고 신인이면 전부다. 횟수도 함께 남긴다: 비율이 같아도 표본이
3회인지 300회인지는 다른 이야기다.

### 혼자 달리지 않는다

경륜은 라인을 짜고 함께 들어온다. 공개 자료에 '오늘 누가 누구와 라인을 짤
것인가'는 없으므로 둘로 대신한다.

* **훈련지 동료 수** — 같은 경주에 훈련지가 같은 선수가 몇인가.
* **동반입상 이력** — 상대전적 API 의 `same_win_tcnt` 를 그 경주의 다른 여섯
  명에 대해 합한 값. **작년 자료만 쓴다** — 상대전적은 그 해 전체의 누적값이라
  같은 해 것을 쓰면 오늘 경주의 결과가 이미 그 숫자 안에 들어가 있다.

화면에서는 이것을 '라인' 이라고 단정하지 않고 **라인 후보**로 적는다.

### 최근 성적이 회전 단위로 온다

회차가 3일 편성이라 최근 3회전 × 3일차 = 아홉 개의 착순이 출주표에 실려 있다.
`"선발 5-1"` 형태로 오는데 **앞이 경주번호, 뒤가 착순**이다. 명세에 설명이
없어 실측으로 확정했다 — 2026-05-23 강석호 `"선발 5-1"` 은 경주결과순위에서
부산 5경주 1착이었고, 같은 날 신호재 `"선발 3-7"` 은 광명 3경주 7착이었다.
뒤집어 읽으면 7착을 1착으로 배우게 된다.

`"결  장"` 은 그 일차에 뛰지 않았다는 뜻이다. 0 이나 7 로 채우면 안 된다 —
**결장은 나쁜 성적이 아니라 성적 없음이다.**

### 선수번호가 출주표에 없다

출주표는 `racer_nm` 만 주고 `racer_no` 를 주지 않는다. 반면 경주결과순위에는
있다. 그래서 **피처와 레이블을 이름으로 잇는다.**

한 경주에 일곱 명뿐이라 경주 안에서 동명이인이 부딪힐 일은 사실상 없다.
위험한 것은 경주를 가로지르는 이름 집계 쪽인데, 그건 연 단위 집계(선수정보·
상대전적)라 같은 위험을 안고 간다. 여기까지가 공개 자료로 할 수 있는 전부다.

### 전개 시뮬레이션 — 바람과 남은 힘

경정의 1턴마크 물리 대신, 경륜은 **드래프팅**을 계산한다. 앞사람 뒤에 붙으면
공기저항이 크게 줄어든다. 그래서 경륜의 전법은 전부 *언제 바람을 맞기 시작할
것인가*의 선택이다.

**주로 제원(333.3m · 1,691m · 5주회)만 사실이고 절감률·소모율은 가정이다.**
그래서 초 단위 숫자는 신뢰할 수 없다. 신뢰할 수 있는 것은 부호와 순서다 —
앞에서 끌면 힘이 빨리 준다, 뒤에 붙으면 아낀다, 아낀 힘은 마지막 직선에서
속도가 된다, 바깥으로 돌면 거리를 손해 본다.

**승률은 시뮬레이션이 내지 않는다.** 승률은 학습된 모델이 낸다. 시뮬레이션은
모델이 못 주는 것 — 전법 분포, 선행 확률, 라인 구도, 전개 대본 — 만 만들고,
화면에서 둘이 다른 말을 하지 않도록 모델 확률에 닻을 내린다.

### ★ 기준을 경정에서 그대로 가져오면 안 된다

경정의 ★ 기준은 '1순위의 2착 이내 확률 0.70' 이었다. 경륜에 그대로 쓰면 ★ 가
**전체의 70% 넘게** 붙는다 — 일곱 경주 중 다섯에 붙는 표시는 아무것도 가리지
않는다. 18,968경주로 다시 보정해 **0.93** 으로 정했다(출현 19% · ★ 1착 81.8% ·
★ 2착 이내 92.0%).

## 배포 (GitHub Pages)

`.github/workflows/publish.yml` 이 매일 자동으로 수집 → 예상 → 빌드 → 배포까지
한다. 처음 한 번만 아래를 해 두면 된다.

1. **저장소 Secrets** 에 `KCYCLE_SERVICE_KEY` 추가 (공공데이터포털 인증키)
2. **Settings → Pages → Source** 를 `GitHub Actions` 로
3. 워크플로를 한 번 손으로 실행(`workflow_dispatch`)

### 언제 도는가

광명 경륜은 **금·토·일**에 시행하고 발주는 11:20~21:20 KST 다.

| 크론(UTC) | KST | 하는 일 |
|---|---|---|
| `30 23 * * *` | 매일 08:30 | 개최일이면 발주 전 예상 게시 / 그 외에는 전날 결과 반영 |
| `30 14 * * *` | 매일 23:30 | 마지막 경주가 끝난 뒤 한 번 더 훑는다 |

**개최일만 돌리지 않는다.** 금·토·일만 돌리면 일요일 결과가 다음 주 금요일까지
닷새 동안 반영되지 않는다.

### 경로 — 이것만 틀리면 전부 404

프로젝트 페이지는 `user.github.io/<저장소>/` 아래에 놓이므로 내부 링크가 모두
그 경로로 시작해야 한다. 워크플로가 `CYCLEAI_BASE=/<저장소명>` 을 넣어 빌드하고,
템플릿은 `{{ base }}` 를 앞에 붙인다. 커스텀 도메인이면 비워 둔다.

```bash
python -m cycleai.site                      # 로컬 (루트)
CYCLEAI_BASE=/cycle python -m cycleai.site  # 배포와 같은 조건으로 확인
```

**함정 하나** — Jinja 매크로는 `{% from %}` 로 불러오면 상위 컨텍스트를 못 받는다.
`with context` 를 빠뜨리면 `{{ base }}` 가 조용히 빈 문자열이 되어 링크가 전부
루트로 나가고, 로컬에서는 멀쩡히 동작하므로 배포 후에야 드러난다.

### 확정 기록은 저장소에 남긴다

발주 전에 확정 저장한 예상은 **잃으면 안 되는 기록**이다. 적중률이 사후
조작이 아니라는 근거가 오직 그것뿐이기 때문이다. 그런데 DB 는 임시 캐시에
있고 캐시는 만료된다 — 그 순간 실전 기록이 통째로 사라진다.

그래서 확정 기록만 따로 `records/frozen.json` 으로 떠서 저장소에 커밋한다
(경주당 7행, 32경주에 177KB). 자동 배포는 매 실행에서 이 파일을 DB 로 되돌리고,
새로 확정한 예상이 생기면 다시 파일로 떠서 커밋한다.

```bash
python -m cycleai.predict export   # DB → records/frozen.json
python -m cycleai.predict import   # records/frozen.json → DB
```

**복원은 이미 있는 행을 절대 덮어쓰지 않는다.** 확정 기록은 한 번 쓰이면
바뀌지 않는 것이고, 되돌리는 과정에서 값이 달라지면 그 기록은 아무것도
증명하지 못한다.

## 통계 (Google Analytics)

`config.yaml` 의 `analytics.ga4_id` 로 켠다. 비우면 스크립트 자체가 나가지 않는다.

**만드는 사람의 접속은 세지 않는다.** 개발 중에는 자기 방문이 전체의 대부분을
차지해, 숫자가 통계가 아니라 자기 그림자가 된다. IP 필터는 주소가 바뀌면 새므로
브라우저에 표식을 남긴다 — 기기마다 한 번씩 아래로 들어오면 그 뒤로는 계속 빠진다.

```
https://cycle.koreanblog.xyz/?noga=1   # 이 브라우저를 집계에서 뺀다
https://cycle.koreanblog.xyz/?noga=0   # 되돌린다
```

## 광고 (AdSense)

`config.yaml` 의 `adsense` 절로 켠다. **client 가 비어 있으면 로더 스크립트도
나가지 않는다** — 설정이 없는데 외부 요청만 나가는 일이 없어야 한다.

`slot_*` 이 비면 수동 광고 자리는 렌더링되지 않는다. 광고 자리는 **본문을 읽은
뒤**에 둔다 — 첫 화면 편성 아래, 상세는 예상판을 읽은 다음.

**사이트 승인은 따로 받지 않는다.** AdSense 사이트 승인은 도메인 단위이고
`koreanblog.xyz` 는 이미 승인된 도메인이라, 서브도메인은 배포 즉시 게재된다.
콘솔에서 할 일은 광고 단위 3개(`cycle.koreanblog.xyz_top` / `_article` /
`_bottom`)를 만들어 슬롯 번호를 채우는 것뿐이다.

## 구조

```
src/cycleai/
  kcycle/        수집 계층
    client.py      GW 클라이언트 (재시도·키 정규화·오류 진단)
    endpoints.py   엔드포인트 레지스트리 + 파라미터 정규화
    probe.py       승인·경로·응답필드 확인
    collect.py     오픈API → SQLite
    normalize.py   응답 → DB 행 (파싱 규칙이 여기 한 곳에만)
    store.py       스키마와 upsert
  clock.py       KST
  korean.py      조사
  features.py    피처 (전법 비율·라인·사전값·경주 내 상대치)
  model.py       학습·워크포워드 검증·추론
  predict.py     예상 확정 저장, 표본외 예측, 기록 보존
  simulate.py    전개 시뮬레이션 (드래프팅)
  marks.py       예상 기호
  calibrate.py   ★ 기준 보정
  verify.py      승식 판정과 적중률·회수율 (절단 포함)
  strategy.py    베팅금·선택 규칙 시뮬레이션
  audit.py       자료 결손 점검
  site.py        정적 사이트 생성
config/openapi/  포털에서 받은 Swagger 명세 원본
docs/            API 신청 목록과 프로브 실측
templates/       Jinja2
static/          CSS
records/         확정 기록 (저장소에 남긴다)
```

## 면책

이 저장소는 개인 학습·분석용이다. 예상은 적중을 보장하지 않으며, 검증 결과
**고배당 한 방에 기대지 않고 100% 를 넘는 방식은 확인되지 않았다.** 투표권
구매를 권유하지 않는다. 19세 미만 구매 불가.
